User guide

WPT Marketing Hub

How to use the hub day to day: what each page does, which buttons change the website, and what to do when something doesn't work.

What the hub is

The hub is your home page for marketing. With no sales team, the website and email are where new leads come from, so the hub keeps the website in shape, tracks every lead you pass to Garry, and keeps campaigns and the weekly brief in one place.

It's a page that runs in your browser from a folder on your laptop. There's nothing to install and no login. It talks to the website through WordPress, using a password you set up once.

It can change the website

Only when you press a button that says so, such as Approve and push live. Every change keeps a backup and has an Undo.

It reads everything else

The audit, Search Console, Google Analytics, the mobile check and the display check only look. They never change anything.

Opening it

  1. Open the folder Desktop\GitHUB\WPT Marketing HUB\wpt-marketing-hub.
  2. Double-click index.html. It opens in your browser.
  3. Bookmark it, or set it as your browser's start page so it's the first thing you see.

The page list is down the left, with this guide at the bottom as User guide. Orange numbers next to a page show how many things are waiting there. The version and build time are at the bottom of the left bar, with a button to switch between light and dark.

Always use the same browser on the same laptop. Your leads, campaigns and settings are saved in that browser. See Where your data lives.

A normal day

  1. Today. See which lead actions are due and what's flagged.
  2. Leads. Paste in any new enquiry with Quick add, so Garry has it. Update the status of anything that's moved on.
  3. Fix queue. Approve a few website fixes. Critical ones first.
  4. Your jobs. Pick off anything only you can do, like an image or a fact to confirm.

Once a week:

  • Monday: run the weekly brief, save it, and pick a blog idea.
  • Website & SEO: run the page audit, the mobile check and the display check, then deal with what they put in the Fix queue.
  • Email campaigns: import results from any send that's had three days to settle.
  • Progress & change log: after the audit, check the health score has moved the right way. Copy the report for Garry when he wants an update.

Website & SEO

The biggest page. Everything on it reads the live site. Fixes it finds go to the Fix queue rather than being made here.

Connect WordPress

Set up once, using an application password from WordPress. Full steps are in docs\SETUP-WORDPRESS.md. When it's working, the box shows who you're signed in as and a green Page checker ready, with the version number. If it says the page checker is out of date, follow Updating the WordPress code.

Page audit

Press Run audit now. It reads every page and post and checks SEO titles, meta descriptions, headings, redirects, word count, schema and more. Problems become fixes in the Fix queue. Run it weekly, and again after a batch of fixes to confirm they've cleared.

The audit also runs the claims check: it searches every page for claims you've said aren't true (BPF, for example). You can change that list on this page. You can also add automatic replacements such as wrong phrase => right phrase, and every page using the wrong phrase becomes a push-ready fix.

Google ranking updates

On Search and traffic. Lists Google's recent core and spam updates from its Search Status Dashboard, with dates. While an update is rolling out, or in the two weeks after it ends, a notice also shows on Today. If clicks or positions jump, check here before changing any pages.

Search performance and Website traffic

Clicks, searches and positions from Google Search Console (through Rank Math), and visits and leads from Google Analytics 4. Press Refresh to update. Pages that get seen but not clicked, and pages sitting just off page one, become fixes.

Mobile and speed

Runs Google's own speed test on every live page, on phones and, with Desktop too ticked, on desktop as well: speed, accessibility and SEO scores, plus anything Google flags. Add the free API key (steps on the page) so it can check every page without hitting Google's limit. Takes 15 to 30 seconds a page.

The table shows the 10 slowest pages. Press Show all to see every page, and Show fewer to fold it back up. If Google doesn't answer for a page, the hub tries it again up to three times. Any still missing can be rechecked with Check the ones that failed again, which keeps the results you already have.

While the audit, mobile check or display check runs, the bar shows how far through it is, roughly how long is left and when it should finish. The first estimate is a guess, and it sharpens after a few pages.

Display check

Looks at every page the way a visitor does. Each page loads once in a small preview, then gets checked at ten screen widths, from a large monitor (1536px) down to a phone (400px), because some problems only appear at certain sizes. It finds:

Press Check every page and stay on the hub page while it runs (about 15 seconds a page). Fixes go to the Fix queue. Each says where it is (the nearest heading) and whether it happens on desktop, phones or both. Each fix says the screen widths where the problem shows. Elementor has three screen types (desktop, tablet up to 1024px, phone up to 767px), and a fix only changes the screen types where the problem was found. A problem found only on phones changes the phone setting only.

It finds what it can measure. It won't judge design, such as one logo tile looking different from the others. Keep sending Claude screenshots of anything that looks off.

The page is split into tabs along the top: Audit, Search and traffic, AI visibility, Speed and display, Content plan and WordPress connection. Click one to see just that group. The hub opens on the last tab you used.

Keyword rankings, AI search visibility and Content plan

Tables you fill in. Rankings: the searches you want to win and where you sit. AI search visibility: each week the hub picks ten of the 30 buyer prompts. Copy each one into ChatGPT (temporary chat) and Google, plus Copilot and Perplexity if you have time. Copy the whole answer back, click Log a result, paste it in and click Score it. The hub works out whether WPT was named, where it came in, who else was named and which pages were cited. Check the scores, fix anything wrong, then Save. Ticks under each prompt show what you have done this week. The prompt list below it holds all 30 and the page that should win each one. Content plan: new pages, rewrites and blog posts, including blog ideas approved from the weekly brief.

Find text on the site

Searches every published page and post, including Elementor pages, for any words. Handy for checking where a claim, a product name or an old phone number appears.

The change log used to sit at the bottom of this page. It now has its own page: Progress & change log.

Fix queue

Everything the website needs, written by Claude or found by the checks. Nothing goes live until you approve it.

Reading a fix

Some text fixes say Your new wording (change it, then push). The hub found the problem but the words are yours to choose, so it won't push until you've changed them.

Each card shows a priority (Critical High Medium Low), the type of fix, the area, and the page it's on. Most show Now on the site next to Proposed, so you can compare them. You can edit the proposed text before approving. Reset to Claude's version undoes your edits.

Tabs and filter

Waiting for you is what's left to do. In progress holds fixes you've started but can't finish yet: click In progress on any fix, pick the date for the next action and add a note if you like. On that date the fix comes back to the top of Waiting for you and shows on the Today page. Change date moves the date and Back in the queue now brings it back early. Done holds pushed fixes, each with its Undo. Not doing holds what you've rejected, and any of them can go back in the queue. The area filter (Content, Mobile, Structure and so on) narrows the list.

Progress log. Fixes you're working through show a Progress log above their buttons. Where a fix covers several vendors (like the partner directories one), each vendor has its own tab with a status (To do, Waiting on them, Done, Not possible), the next step, and a dated list of what's happened. Claude's entries are marked Claude. Add your own with the date and a line of text, then Add to log. Change the status from the dropdown. Your own entries and statuses are saved in this browser. When Claude sends an update, the fix moves to In progress with the next action date it gives.

The claims card

Lists every page still making a false claim, each with its own Push the fix. Pages already fixed say Fix pushed. Check the site again now re-runs the check, and the card disappears once the site is clean.

New page builds

Press Check the look to see the fonts, sizes and colours the new page will copy. When Claude has written the page, Push new page build for review makes the draft and gives you Preview the draft and Edit in Elementor. You need to be logged in to WordPress in the same browser to see the preview. Bin this draft moves it to the WordPress bin.

Undo

On any pushed fix, click Undo twice. If the page has been edited since, the hub warns you, because undoing would also remove those later edits. You can still go ahead, or use Revisions in Elementor instead.

Progress & change log

Shows how the website's scores have moved since your first audit, and lists every change the hub has made to the site. It sits under Fix queue in the left menu. Use it to prove the SEO work is paying off.

Snapshots

Every time you run the page audit on Website & SEO, the hub saves that day's scores as a snapshot. The first one is your baseline, the starting point everything else is measured against. If you'd already run an audit before this page existed, that audit becomes the baseline the first time you open the page, dated the day it ran.

There's one snapshot per day. Run the audit twice in a day and the second run replaces the first.

If you've updated keyword positions or AI search answers without running the audit again, press Save today's snapshot. It saves today's figures using the last audit.

The health score

The headline number. It's the percentage of all page checks the site passes. Each page is checked for twelve problems: thin content, missing meta description, meta description too long or short, title over 60 characters, missing or extra H1, no H2s, images without alt text, few internal links, not updated in a year, set to noindex, canonical pointing elsewhere and not loading properly. Pages that redirect elsewhere aren't counted.

Fix a missing meta description on one page and the score goes up a little. Clear every problem on every page and it reads 100%.

Comparing two dates

Pick any two snapshots in Compare from and To. By default it compares your baseline with the latest one. Every measure then shows:

  • the figure on each date
  • the change, such as -14 or +8.3 pts
  • the change as a percentage, such as 56% better or 12% worse

Green means better and red means worse. For issues and keyword positions, lower is better, so a drop shows green.

As well as the page checks, the scorecard includes average mobile and desktop speed scores (from the last speed check before each snapshot), your average keyword position, keywords in Google's top 10 and how many AI answers name WPT. Those last three come from the tables on Website & SEO, so they only mean something if you keep them up to date.

The rest of the page

  • Health score over time. A chart of every snapshot. Hover the line for the figure on each date.
  • Pages that moved. Pages whose issue count changed between the two dates, biggest improvements first.
  • Website changes made. How many fixes were pushed live in that period. Undos and fixes marked done without a push aren't counted.
  • Snapshot history. Every snapshot, with a Delete button (click twice) if one was taken by mistake.

Copy report for Garry

Appears once you have two snapshots. It copies a plain-text summary of the comparison, ready to paste into an email: each measure before and after with its percentage, the number of website changes and the five most improved pages.

Change log

At the bottom of the page. Every change the hub has made to the website, newest first: what, where and when, including undos. Copy as CSV copies the whole log.

Snapshots are saved in your browser, like your leads. Press Copy history as CSV now and then and paste it somewhere safe, such as a spreadsheet, so you don't lose your baseline if the browser data gets cleared.

Your jobs

Things only you can do: make an image in Canva at the size given, confirm a fact, get a sign-off from Garry. Claude adds to this list with each batch of fixes. Set each one to Doing or Done as you go.

Claude can also move a job on from its end, for example marking it Doing once something has been sent off. That change arrives when you pull from GitHub. If you then change the status yourself, yours sticks.

Leads

Every lead you pass to Garry, so you both know where each one stands.

Quick add

  1. Paste a lead into the box. Any of these work: a website form email, an ordinary email or a whole email thread, a call brief, or a rough note like Michael Smith - Guitartech shop - London - 07432345434 - wants 3CX - 14 users.
  2. Click Add lead, or press Ctrl+Enter.
  3. Check the new row. Fix any cell by clicking into it.

It fills in the date, company, contact, phone and email, source and what they want. It sets the owner to Garry, the status to New and the chase date to the next working day. It skips WPT's own people, phone numbers and signatures. If the lead's already in (same email or company), it warns you rather than adding it twice.

The tracker

Each row is a short summary. Press Brief at the start of a row to open the Lead brief: the full story pasted in, which you can edit. Hide closes it. Remove deletes the lead after you click again to confirm.

The counts across the top show how many leads are at each status. Keep the status, next step and next step date up to date and the Today page will remind you when things are due.

Garry can't see this list yet. It's saved in your browser only. Use Copy as CSV or Download CSV to send it to him. Both include the lead briefs.

Email campaigns

One row per send, with opens, clicks, bounces and unsubscribes. The rates work themselves out. Contact lists come out of Quistor as spreadsheets and go into iContact:

  1. Export the list from Quistor.
  2. Clean it: duplicates, role addresses (info@, sales@) and opt-outs.
  3. Upload to iContact and send.
  4. After three days, export the results from iContact and import the CSV here, under Import an iContact results export.
  5. Anyone who clicked is worth passing to Leads for Garry.

Live chat

A log of website chats, ready for the 8x8 AI chatbot replacing the current one. Mark a chat's outcome, and for a real enquiry press Send to Leads to put it straight into the lead tracker for Garry. The page shows how many chats turned into leads.

Weekly brief

  1. Every Monday, copy the brief prompt from this page into Claude or ChatGPT.
  2. The brief now has a Search and AI search changes section: Google, Bing, Copilot and ChatGPT changes from the last week that affect our site, or "Nothing this week".
  3. Paste the finished brief into This week's brief and click Save brief. Past briefs stay listed underneath.
  4. Add the strongest items as Blog ideas, with the search each post should win. Press Approve on one and it moves to the Content plan on Website & SEO.

Inbox triage

For the emails that need you, in order: leads, then partners (8x8, Gamma, 3CX, Zoom Phone), then complaints, then important updates. It will only ever have read-only access. It will never send, reply, delete or move an email.

Outlook isn't connected yet. It needs a Microsoft 365 connection with read-only mail permission, which Matt will need to approve. Until then, log anything you want tracked in the Flagged emails table.

Asking Claude for changes

New fixes, features and fixes to the hub itself come from Claude. The quickest way:

  • Say what you want in plain words. Screenshots help a lot, especially of the website.
  • For a fix card that only has steps, ask Claude to make it push-ready.
  • If something in the hub looks wrong, copy the card or the error message into the chat.

Claude writes changes straight into the hub folder. Refresh the hub page to see them. The version number at the bottom of the left bar goes up each time.

Saving versions (GitHub)

Changes are on your laptop as soon as Claude makes them. GitHub keeps restore points and an online copy, in case something breaks or the laptop dies.

  1. Open GitHub Desktop. The changed files are listed on the left.
  2. If there are changes, type a short label in Summary. Claude gives you one at the end of each change, for example v0.15.0 display check on every page.
  3. Click Commit to main.
  4. Click Push origin at the top.

If Claude worked in a session running on your laptop, the commit is already done and you only need to Push. The yellow warning about LF and CRLF line endings is harmless.

Every version is listed in CHANGELOG.md in this folder, with the date and time and what changed.

Updating the WordPress code

Some features need a small piece of code in WordPress, called the page checker. When Claude says it needs updating, or the hub says Page checker out of date:

  1. In the hub, go to Website & SEO and click Copy page checker code.
  2. In WordPress, go to Snippets, then All Snippets, and click WPT Hub page checker.
  3. Delete everything in the code box, paste, and click Save Changes.
  4. Back in the hub, click Save and test. It shows the version number, which should be 10.

The page checker only reads your own site. It changes a page only when you approve a fix in the hub.
